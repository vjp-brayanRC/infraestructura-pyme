# Revisión del proyecto

## Conflictos y resolución

Durante el desarrollo del proyecto surgieron algunos conflictos, principalmente al trabajar en paralelo sobre los mismos archivos. En algunos casos, Git detectó *merge conflicts* al intentar fusionar ramas.

Estos problemas se resolvieron revisando manualmente los cambios, comparando versiones y decidiendo en equipo qué contenido conservar o combinar.

---

## Comandos de Git más utilizados

Los comandos que más usamos fueron:

- `git clone` → para copiar el repositorio
- `git add .` → para añadir cambios
- `git commit -m "mensaje"` → para guardar cambios
- `git push` → para subir cambios al repositorio remoto
- `git pull` → para actualizar el repositorio local
- `git branch` → para gestionar ramas
- `git merge` → para unir ramas

---

## Qué haríamos diferente

En un futuro proyecto mejoraríamos varios aspectos:

- Trabajar con ramas más pequeñas y frecuentes
- Hacer commits más claros y atómicos
- Coordinar mejor los cambios para evitar conflictos
- Usar más revisiones de código entre compañeros

---

## Intercambio de roles

El intercambio de roles funcionó de manera positiva, ya que permitió que todos participáramos en distintas tareas (desarrollo, revisión y organización).

Esto ayudó a entender mejor el proyecto en su conjunto, aunque al principio hubo un pequeño periodo de adaptación al cambiar de responsabilidades.
